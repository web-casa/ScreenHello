# 商店适配第三阶段：MAS 保存目录授权

日期：2026-09-17。承接[第二阶段](./desktop-store-phase-2-2026-09-17.md)。本轮实现显式目录授权方案与取消处理；不是已经完成 MAS 实机验收的声明。

## 问题与选择

`write_atomic` 在输出文件的同目录创建临时文件，再按已确认覆盖或禁止覆盖策略提交。选择一个文件不能用来推定有权创建其兄弟临时文件，也不能推定追加扩展名后的路径具有相同授权。[Apple 沙箱文件访问说明](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox) 区分文件与目录的授权范围；系统面板对所选 URL 提供访问，目录选择覆盖其内容。不能仅因未使用 bookmark 就断言系统面板文件读取必然失败。

本轮采取显式选择目标目录的方案，不扩大 entitlements，不取消原子写入，不把路径当作跨进程重启的授权凭据。NSFileCoordinator/原生 URL 生命周期和持久化 bookmark 仍可作为后续降低操作次数的方案，需真实 macOS 验证后再替换。

## 用户行为与实现

- **仅开启 `mac-app-store` feature 的构建**在每次写入前显示目标文件夹选择面板，初始位置为输出目录。直装 macOS、Windows、Linux 与 Web 的保存步骤保持原状。
- 面板说明“请选择目标文件所在文件夹，以授权安全保存”，沿用现有原生中文/英文机制。这是明确的交互成本：当前每次保存均需确认，包括打开项目后的覆盖保存、导出与预设；尚未缓存或持久化目录授权。
- 所选目录必须与实际最终输出路径的父目录 canonical path 一致。错误目录、文件而非目录、取消、无法解析路径均拒绝写入。这里的路径核对不是完整的文件系统 TOCTOU 防护，不宣称能抵御外部进程并发替换目录。
- 原生文件路径不经 IPC 暴露。授权面板关闭后重新验证 token 所有者及目标对象身份，拒绝弹窗期间已释放或被重新绑定的 token。
- 取消返回固定取消代码；前端返回 cancelled，不将项目标为已保存、不更新最近项目或弹成功/失败通知。新申请而未采用的句柄释放，已持有的句柄保留供重试。
- 选错目录提供七语言提示。授权面板仍沿用原生仅中文/英文的既有范围，不冒称整个原生界面已覆盖七语言。
- 保留原有扩展名追加后的 CreateNew 防覆盖、成功后才允许后续覆盖、临时文件 sync 和原子提交机制。

## 验证

- Linux 主机 Rust 默认 feature 与 `mac-app-store` feature 单测：各 44 项通过。
- 相关 JS 单测：38 项通过；覆盖取消后不标记保存、不弹误导消息、新句柄释放、现有句柄保留、错误代码转换。
- 新增 Rust 用例检查准确目录、取消、文件代替目录、校验不产生文件，以及原子提交冲突保留旧字节并清理临时文件。
- `pnpm lint`、`pnpm typecheck`、`pnpm audit:i18n`、`cargo fmt --check`、Web/桌面前端构建通过。国际化 652 个键，无缺失或占位符问题。
- 初次新增 JS 用例误用了不存在的 harness 名称而失败；改为测试文件已有 createRuntime 后重跑通过。

上述 feature 测试只证明 Linux 环境中的逻辑/编译分支，不证明 macOS Powerbox 权限实际可用。未生成、签名或安装新的 MAS 包；未执行真实取消面板、TCC、沙箱及外部磁盘验收。
